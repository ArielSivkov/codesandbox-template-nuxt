# esh27-mp – שרת מרובה משתתפים (לא נפרס)

שרת קטן ל"לוח היזם · עולם תאום": שחקנים באותו חדר רואים זה את זה כ"רוחות" (דמות / רכב / כלי טיס פשוטים).
Cloudflare Worker + Durable Object אחד לכל חדר. הלקוח: `twin/integration/world/adapters/65-multiplayer.js` – פועל רק עם `?mp=<חדר>`.

## הרעיון מ-earth1926 (server/main.go) ומה שונה
| main.go (Go, gorilla/websocket) | esh27-mp |
|---|---|
| מזהה שחקן מהשרת | אותו דבר (8 תווים אקראיים) |
| מצב: מיקום, סיבוב Y, חיים, ברכב | מיקום ITM אמיתי (E/N), גובה, כיוון, מצב (רגלי/רכב/מסוק…), מהירות, כוכבי "מבוקש" – בלי "חיים" |
| שולח את **כל** המפה לכולם 30 פעמים בשנייה | מפיץ כל עדכון מיד לשאר החדר; הלקוח שולח ~5 פעמים בשנייה ומחליק (interpolation) |
| כל מקור מתקבל (`CheckOrigin: true`) | רק המקורות שלנו (githack, esh27.com, workers.dev שלנו, localhost) |
| ללא בדיקת ערכים | מספרים סופיים בתחום ישראל, מצב מרשימה, שם מנוקה, הודעה עד 512 תווים, עד ~8 הודעות בשנייה לשחקן |
| חדר אחד לכל השרת | חדר לפי שם (`/room/<שם>`), עד 24 שחקנים |
| שרת שרץ כל הזמן | WebSocket Hibernation – כשאין הודעות האובייקט "ישן" ולא נספר זמן |

## פרוטוקול
- `GET /health` → `{ok, v, rate, max}`
- `GET /room/<שם>?n=<כינוי>` (שדרוג ל-WebSocket)
- לקוח → שרת: `{"t":"s","E":164751.2,"N":634164.0,"y":12.3,"h":1.57,"m":"car","v":8.2,"w":1}` · `{"t":"ping"}`
- שרת → לקוח: `{"t":"hi","id","nm","room","rate","max","peers":[…]}` · `{"t":"s","id","nm",…}` · `{"t":"bye","id"}` · `{"t":"pong"}` · `{"t":"full","max"}` (ואז סגירה 4001)

## פריסה – רק באישור אריאל
```
cd twin/servers/esh27-mp
npx wrangler deploy
```
- הכתובת שהלקוח מנסה כברירת מחדל: `wss://esh27-mp.ariel-sivkov.workers.dev` (אותו חשבון כמו esh27-accounts / esh27-telemetry). `?mpsrv=<wss://…>` מחליף.
- התוכנית החינמית: Durable Objects מבוססי SQLite זמינים בה (לכן `new_sqlite_classes`). מכסה יומית: 100,000 בקשות ל-Durable Objects, ובהן גם הודעות WebSocket.
  חשבון גס: שחקן אחד = 5 הודעות בשנייה = 18,000 בשעה. **[לא אומת]** – לפי מסמכי קלאודפלייר הודעות WebSocket נכנסות נספרות ביחס מוזל (20 הודעות = בקשה אחת); אם כך, ~110 שעות-שחקן ביום בחינם, ואם לא – ~5.5 בלבד. לבדוק בלוח הבקרה אחרי יום ראשון.
- אין אחסון קבוע (רק זיכרון). אחרי "שינה" רשימת השחקנים מתמלאת שוב מהעדכון הבא (~200 מ"ש).

## בדיקות
`node twin/integration/tools/test-mp.js` – בודק גם את המחלקה `Room` עם שקעים מדומים (הצטרפות, הפצה, ניקוי ערכים, הגבלת קצב, חדר מלא, יציאה).
